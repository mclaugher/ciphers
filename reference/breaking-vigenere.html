Breaking the Vigenère Cipher

The whole attack on one card. It is two old tools in sequence: Kasiski to find the key length, then frequency analysis run once per column.

Step 1 · Find the key length (Kasiski examination)

repeats betray the period
  1. Scan the ciphertext for repeated runs of 3+ letters. A repeat usually means the same plaintext met the same slice of the key.
  2. For each repeat, measure the distance (number of letters) between its occurrences.
  3. The key length divides every distance — so take the greatest common divisor (GCD) of the distances. That GCD (or a small factor of it) is the key length n.

Example: gaps of 60, 45 and 20 → gcd = 5 → the key is 5 letters long.

Step 2 · Split into columns

one polyalphabetic → n monoalphabetic Write the ciphertext into n columns, dealing letters across like cards: column 1 gets letters 1, n+1, 2n+1, …; column 2 gets 2, n+2, …; and so on. Every letter in a column was shifted by the same key letter — so each column is a Caesar cipher.

Step 3 · Solve each column by frequency

the Lesson 02 move, n times In each column, find the most common letter. Assume it is E (the commonest English letter). The shift that turns it into E is that column's key letter:
key letter = (most-common-letter − E) mod 26
  decrypt: P = (C − key letter) mod 26
Collect one key letter per column → the keyword. Decrypt the whole message and read it; if a column looks wrong, its top letter wasn't E — try the next most common (T, A, O) for that column only.

When it gets harder

Short messages give thin columns where E may not dominate — gather more text, or test the top few candidates per column. Computers skip Kasiski and use the index of coincidence to estimate the key length, then do the same column-wise frequency attack.
